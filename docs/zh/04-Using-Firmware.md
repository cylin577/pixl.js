# 概念
## Amiibo

Amiibo是任天堂销售的游戏周边，通常呈现为一个游戏角色的手办，但也包括卡片、手腕带等其他形式。

每个Amiibo都在手办底座上嵌入了一个NFC标签。NFC标签在工厂预先记录了一些数据，用于识别手办的类型，使每个Amiibo与其他不同。
在一些游戏中（特别是任天堂发布的一方游戏）扫描NFC标签可以获得游戏中的道具等。

## Model Info
这是一个数字，用于描述Amiibo系列、游戏系列、角色和角色变体，此信息在首次编程后无法更改。

## Amiibo ID
用于识别Amiibo手办，手办序列号也是在工厂硬编码的，使得每一种手办都有自己的编号，且能通过Amiibo ID识别是哪一种手办。

## Amiibo Data
标签上的数据的这一部分存储了用户可修改的信息，如所有者和昵称的注册信息或游戏存档数据。

## NTAG215
NTAG215是NXP公司出售的一种NFC卡片，可以用来存储数据在卡片上。使用NFC读卡器可以读取或者写入NTAG215里面的数据。

Amiibo就是使用NTAG215卡片存储数据的。

## UID
为NTG215卡片的卡号。每个NTAG215都有一个7个字节的唯一的卡号。

在修改场景中，术语UID用于引用由Amiibo模拟器发送给游戏的UID，因为游戏使用UID来判断是否已经使用了Amiibo。如果模拟器更改了UID，模拟的Amiibo在游戏中看起来就像是完全不同的Amiibo，从而允许再次使用该Amiibo。

## key_retail.bin
这是一个包含任天堂用于加密Amiibo的私钥的二进制文件，是受版权保护的材料，因此您需要提供一个合法获取的文件，您可以从3DS或Switch主机中导出它。

## .BIN file
Amiibo的数据可以被导出到一个文件，该文件以.BIN扩展名存储了Amiibo原始内容的二进制转储。这些转储文件被上传到设备上供Amiibo模拟器应用程序或AmiiboLink模拟器应用程序使用。您需要提供一个合法获取的二进制转储文件。

通常大小是540字节，但是有些文件可能是不太常见的532字节或者572字节，但是`Amiibo模拟器`应用都能很好的使用。

## 多功能按钮
这是设备顶部的微型开关，是一个具有三个按钮的设备，一个“**中键**“和两个“**侧边**”按钮。将微型开关推向两侧会按下“侧边”按钮。按下微型开关时，会按下“中间”按钮。

在本文档中，按下多功能按钮的两侧被称为“**左键**”和”**右键**“，按下多功能按钮被称为“**中键**”；在菜单中导航项目时，使用侧面按钮，要选择一个项目，请按下”中间“按钮。长按”**中键**“超过1秒钟可以进入上下文菜单。

# Amiibo模拟器

这个应用程序允许您浏览本地存储中的 .BIN 文件，并将它们用作当前的Amiibo。

您可以使用拇指滑轮滑动开关浏览文件夹和文件，推动到两侧可以更改元素，按下中间按钮可以选择突出显示的元素。

一旦选择了一个 .BIN 文件，其数据就会被用作当前的Amiibo，屏幕显示当前Amiibo的详细信息，如Amiibo当前UUID、文件名和Amiibo名称。

## Amiibo详情

您可以使用侧面按钮在当前文件夹中切换到下一个或上一个Amiibo。按下中间按钮，您可以更改当前Amiibo的行为，在子菜单中：

| ------------ |

| 自动随机生成 [开] |
| 删除标签 | 
| 返回详情 |
| 返回文件列表 |
| 返回主菜单 |

* 随机生成：更改呈现给游戏的当前Amiibo的UID。新的UID会保持不变，直到您更改当前Amiibo或再次选择此选项。
* 自动随机生成：打开此功能将为当前Amiibo生成一个新的随机UID，每次游戏读取它时都会生成一个新的UID。这允许在具有限制的游戏中多次使用同一Amiibo。

_如果启用UID的随机生成（无论是手动还是自动），则在下一次加载该文件时将使用该文件的原始UID。_

# Amiibo数据库

此应用允许从已知的Amiibo列表中模拟Amiibo，它使用合法获得的信息（例如Model Info），当您选择某个Amiibo时，系统会使用一个随机UUID在内存中创建一个新的虚拟Amiibo。要使用此应用，您必须提供您的«key_retail.bin»文件。

_每次使用Amiibo时，初始UUID都会随机生成。_

该数据库使用Amiibo模型数据创建虚拟标签。依赖存档数据（savedata）或加密应用区域的效果（例如《旷野之息》中的20颗心的狼林克）并不包含在数据库条目中。要使用这类依赖存档的行为，请在Amiibo模拟器中使用您自己合法获取的`.BIN`转储文件。

# AmiiboLink

此应用模拟一个AmiiboLink（AmiLoop或omllbolink）设备。

这些设备是以不同形式出售的通用espruino开发板，通常为水滴形状的挂件钥匙扣，也有一些是Puck或希卡石板形状。

它们几乎都有一个按键和一些用作指示灯的LED，使用CR2032纽扣电池或锂电池供电。

它们都通过手机应用程序经蓝牙控制，您也可以使用手机向设备上传一个或多个.BIN Amiibo文件。

启动此应用后，会显示当前Amiibo的详情。如果您处于按序模式，可以使用侧键在所有已上传的Amiibo之间切换；在所有模式下，都可以按中键打开AmiiboLink应用配置子菜单，菜单包含以下项目：

|   |
| ------------ |
| 模式 []<BR>自动随机 []<BR>兼容模式 []<BR>[标签详情]<BR>[主菜单] |
|   |

## 模式 []
显示当前的工作模式，选中后可以选择Amiibo的工作模式，可用的模式有：
- ### 随机(手动)
在实际的AmiiboLink设备上，按下设备上的按键时，当前Amiibo会更换UUID
- ### 随机(自动)
每次游戏读取当前Amiibo后，都会为它生成一个新的随机UUID。这允许在具有限制的游戏中多次使用同一Amiibo。在此模式下您无法切换当前Amiibo。
- ### 按序模式
在此模式下，您可以使用侧键切换当前的Amiibo，在所有使用手机应用上传的Amiibo之间循环切换。所有上传的.BIN文件都存储在/amiibolink/文件夹下的01.bin到26.bin文件中。
- ### 读写模式
设备使用一个"特殊"的Amiibo槽位，其中只能使用一个Amiibo，该Amiibo可以通过手机应用替换为另一个.BIN文件。此Amiibo在本地存储中保存为/amiibolink/99.bin文件。

切换模式会保留当前选中的Amiibo，«读写模式»除外。

## 兼容模式 []
显示模拟的固件模式，支持的取值为V1(历史版本)、V2(最新版本)和AmiLoop，有多种手机应用分别针对某个AmiiboLink固件版本或AmiLoop协议设计。使用此设置可以让模拟与您手机上应用所需的协议相匹配。
## [标签详情]
返回Amiibo详情页
## [主菜单]
退出AmiiboLink模拟器应用。

# 卡模拟器

这个应用可以用来模拟Mifare卡片和NTAG系列卡片。

Mifare卡片常见用于门禁卡，设备可以支持完整模拟Mifare类型的卡片。支持Mifare卡片类型有：

* Mifare Mini
* Mifare 1K
* Mifare 2K
* Mifare 4K

NTAG系列卡片常用于设备识别。支持的NTAG卡片类型有：

* NTAG 210
* NTAG 212
* NTAG 213
* NTAG 215
* NTAG 216
* Mifire Ultralight C
* Mifire Ultralight C
* Mifire Ultralight EV1(640 bits)
* Mifire Ultralight EV1(1312 bits)

目前总共支持存储8张卡片，后续开放自定义卡片数量。

> **注意**：<br/> 
新建的NTAG卡片按照NXP出厂状态初始化：静态锁位已清零，并带有有效的NDEF容量容器（CC）和空的NDEF TLV，可以像全新的NTAG白卡一样直接被NFC读卡器或手机写入。 <br />
通过NFC写入的数据会保留在卡槽数据中，退出卡模拟器或设备休眠时写入闪存。 <br />
旧版本固件创建的卡片可能已置锁位而拒绝写入，可在卡片菜单中使用「卡数据 → 重置」恢复为可写的出厂状态。

只有在此界面才开启模拟功能，如果离开这个界面就会关闭模拟。

在磁盘格式化后或者第一次进入卡模拟器会初始化数据，这个过程可能需要几秒钟，请稍微等待下。

## 卡名修改

在此界面可以修改卡的名字。

由于显示区域有限，只能输入英文字符。

特别的，如果是中文字符，由于utf8编码的原因，删除请至少按2次才能完全删除。

如果想给卡片写中文备注，可以通过网页修改 `/chameleon/slots/00.bin`的备注来实现中文备注。<br />
00.bin为第一个卡槽文件，01.bin为第二个卡槽文件以此类推。

> 由于固件大小限制，目前仅有1000个左右的中文字符可以正常显示，如果输入中文没有显示，请提issue写上需要显示的字符，下一个版本可以加上特定的字符。

如需要导入数据，则需要提前通过网页把需要导入的数据文件写入到上面的文件夹。

* 加载：按中键可以进入加载界面，界面会读取`/chameleon/dump/`下面所有文件，按中键可以执行导入。
* 导出：按中键可以将当前的卡片导出到`/chameleon/dump/`文件夹下。
* 重置：按中键可以重置当前卡片数据为默认内置的空卡片数据。

> 加载的文件大小必须和当前卡类型完全一致才能导入。不同卡片的数据文件大小参考`模拟卡界面`表格。


## 卡高级设置

这个界面根据MiFare系列卡片和NTAG系列卡片显示不同的内容。

> **特别注意**：<br/>

### MiFare系列
|   |
| ------------ |
|  自定义模式 [关] |
|  ID [de:ad:be:ef]|

|  Gen1A模式 [关] |

* 自定义模式：默认为关。关：ID卡识别阶段的ID/SAK/ATQA从卡片数据的0扇区读取，开：可以在下面ID/SAK/ATQA菜单设置独立的资源。
* ID: 显示当前卡ID。如果自定义模式为开，按中键可以进入输入界面修改。自定义模式为关，按中键不生效。
* SAK: 显示当前卡SAK。如果自定义模式为开，按中键可以进入输入界面修改。自定义模式为关，按中键不生效。
* ATQA：显示当前卡ATQA。如果自定义模式为开，按中键可以进入输入界面修改。自定义模式为关，按中键不生效。
* Gen1A模式：默认为关。开启后，允许模拟器响应国产高级后门指令。这些后门指令可以直接解锁卡，而无需密钥。
* Gen2模式：默认为关。开启后，允许写入0扇区。 (0扇区主要存放了ID/SAK/ATQA这些信息，允许写入则可以修改卡片的ID)
* 写入模式：默认为正常。可以有4个值，见下表。

|  写入模式 | 说明 |
| ----- | --- |
| 正常 | 数据正常写入到内存，切换卡或者退出保存 |
| 拒绝 | 写入任何操作返回失败 |
| 忽略 | 写入操作返回成功，但是不写入内存也不保存 |
| 缓存 | 数据正常写入内存，切换卡或者退出不保存 |

> Gen1A模式和Gen2模式建议在复制卡时候打开，复制完卡后关闭，避免被读卡器识别为克隆卡。

## 版本
此子菜单显示固件的版本详情。
- 版本
- 构建日期
- Githash
- 分支
- 目标
- Dirty
## 系统语言
可以更改设备上显示的语言。此固件内置英文和简体中文；编译的语言集合在`fw/data/i18n_languages.txt`中配置，通过在其中添加`fw/data/i18n.csv`中的其他语言并重新编译固件即可启用。
## 外置存储
可以在这里查看外置存储的状态和容量，进入此菜单可以查看外置存储的使用详情并执行格式化操作。
## 背光亮度 / 亮度
通过此设置可以控制LCD屏幕背光亮度，或者OLED版本的屏幕亮度（显示为**亮度**）。
## 动画效果
启用/禁用超出屏幕大小的菜单项的动画，以便完整阅读它们。启用此选项会增加电池消耗。
## LiPO电池
启用锂电池电压配置文件。它需要硬件上具有可充电锂电池并连接到预期的电池检测和充电电路。此选项本身不会增加充电支持。

一些OLED设备销售时带有可充电电池，但仅有OLED并不能说明该板符合此固件预期的锂电池硬件。如果设备使用CR2032纽扣电池，或者您不确定电池电路的接线方式，请保持此选项关闭。

如果启用LiPO选项，设备将使用锂电池电压水平来显示电量，并且在电池处于充电模式时还可以显示充电标志。
## 内存使用率
在屏幕底部显示存储内存的使用百分比。
## 快速唤醒
启用设备休眠功能，使游戏读取当前amiibo时响应更快，并且在休眠时恢复到休眠前打开的应用；禁用此功能后，唤醒要多花1秒时间，并且设备恢复到主菜单。
## 屏幕翻转
将整个用户界面旋转180度。当您旋转设备持有时非常有用，例如右手使用时。此选项只影响显示；如果您还想让左右导航跟随旋转后的视角，请将它与**按键互换**组合使用。
## 按键互换
交换左右按键。当设备被旋转持有时，或者您只是喜欢镜像导航时，启用此项。
## 休眠时间
设置设备在最后一次用户输入或amiibo读取后进入休眠的时间。
## 应用管理
禁用或启用显示在主菜单上的应用。
## 进入休眠
手动让设备进入休眠模式。
## 固件更新
此选项将设备置于DFU模式，允许OTA固件更新，您可以使用iNFC或网页更新固件。

您可以访问网址 [https://thegecko.github.io/web-bluetooth-dfu/](https://thegecko.github.io/web-bluetooth-dfu/) 上传固件，该页面也可以通过官方网站 [https://pixl.amiibo.xyz/](https://pixl.amiibo.xyz/) 打开。
## 重启设备
允许您重启设备，回到拆卸并重新安装电池后的状态。

## 重置默认配置
将所有设置重置为默认值。

## 关于设备
显示Pixl.js项目信息，包括源代码仓库、许可证等。
