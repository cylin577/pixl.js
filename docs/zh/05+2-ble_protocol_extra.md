# BLE 控制平面（常駐）

本文描述 Pixl.js 的 **BLE 控制平面**，一個常駐的精簡 BLE 介面。
它獨立於 `05+1-ble_protocol.md` 中基於 Nordic UART Service (NUS) 的檔案傳輸協定，
即使裝置不在檔案傳輸模式下也始終可用。

它僅暴露 **兩個命令**：

1. 進入正常 BLE 檔案傳輸模式。
2. 進入控制模式，主機傳送 3 個輸入，對應 3 個實體按鈕。

## 服務

- 服務名稱：Pixl Control Plane
- 服務 UUID：`7e400001-b5a3-f393-e0a9-e50e24dcca9e`
- 特徵（寫入 / 無回應寫入）：`7e400002-b5a3-f393-e0a9-e50e24dcca9e`（Control TX）
- 特徵（通知）：`7e400003-b5a3-f393-e0a9-e50e24dcca9e`（Control RX）

控制平面在裝置通電且 BLE 開啟時即廣播。進入檔案傳輸或控制模式不會停用它，
只會改變目前的活動模式。

## 封包格式

與檔案傳輸協定相同的 4 位元組標頭：

| 欄位 | 型別 | 長度 | 說明 |
| ---- | ---- | ---- | ---- |
| cmd | uint8 | 1 | 命令 id |
| status | uint8 | 1 | 請求固定 0；回應為狀態碼 |
| chunk | uint16 | 2 | 0（無分塊；控制封包單一 ATT 寫入） |
| data | byte | N | 命令相關資料 |

數值型別為無號整數，小端序。不使用分塊傳輸，每個命令都可容納於一次 ATT 寫入。

## 狀態碼

| 代碼 | 說明 |
| ---- | ---- |
| 0x00 | 成功 |
| 0x01 | 一般錯誤 |
| 0x02 | 無效的模式切換（例如已在目標模式） |
| 0xFF | 未知命令 |

## 命令 0x01：進入正常 BLE 檔案傳輸

將裝置切換至正常 BLE 檔案傳輸應用程式（NUS 協定，見 `05+1-ble_protocol.md`）。
成功後裝置開始廣播檔案傳輸服務，控制平面仍保持可用以切換模式。

請求：

| 欄位 | 型別 | 長度 | 值 |
| ---- | ---- | ---- | ---- |
| cmd | uint8 | 1 | 0x01 |
| status | uint8 | 1 | 0 |
| chunk | uint16 | 2 | 0 |

回應：

| 欄位 | 型別 | 長度 | 值 |
| ---- | ---- | ---- | ---- |
| cmd | uint8 | 1 | 0x01 |
| status | uint8 | 1 | 成功為 0x00 |
| chunk | uint16 | 2 | 0 |

## 命令 0x02：進入控制模式

將裝置切換至控制模式。在此模式下，主機透過軟體驅動 3 個實體按鈕。
進入控制模式期間，裝置不處理實體按鈕的按壓（由軟體輸入接管），直到退出控制模式。

請求：

| 欄位 | 型別 | 長度 | 值 |
| ---- | ---- | ---- | ---- |
| cmd | uint8 | 1 | 0x02 |
| status | uint8 | 1 | 0 |
| chunk | uint16 | 2 | 0 |

回應：

| 欄位 | 型別 | 長度 | 值 |
| ---- | ---- | ---- | ---- |
| cmd | uint8 | 1 | 0x02 |
| status | uint8 | 1 | 成功為 0x00 |
| chunk | uint16 | 2 | 0 |

### 按鈕輸入（僅控制模式）

進入控制模式後，主機在同一 Control TX 特徵上以 cmd `0x03`（控制模式的子命令）
傳送按鈕狀態更新。每次更新包含 3 個位元組，依固定順序對應 3 個實體按鈕：

| 位元組 | 按鈕 | 值 |
| ---- | ---- | ---- |
| 0 | 按鈕 A（左） | 0 = 放開，1 = 按下 |
| 1 | 按鈕 B（中） | 0 = 放開，1 = 按下 |
| 2 | 按鈕 C（右） | 0 = 放開，1 = 按下 |

封包：

| 欄位 | 型別 | 長度 | 說明 |
| ---- | ---- | ---- | ---- |
| cmd | uint8 | 1 | 0x03 |
| status | uint8 | 1 | 0 |
| chunk | uint16 | 2 | 0 |
| btnA | uint8 | 1 | 0/1 |
| btnB | uint8 | 1 | 0/1 |
| btnC | uint8 | 1 | 0/1 |

裝置立即套用狀態並在軟體端消抖。`0x03` 更新不回應（射後不理），以降低延遲。
非控制模式下傳送 `0x03` 會被忽略。

## 退出模式

- 若要離開控制模式回到閒置，傳送命令 `0x01`（進入檔案傳輸）或重新開機。
  沒有獨立的「退出控制模式」命令；模式切換一律由兩個頂層命令之一發起。
- 實體按鈕的長按行為不變；控制平面僅在控制模式下接管按壓。

## 備註

- 控制平面常駐；模式狀態保存於 RAM，重新開機即重置。
- 同一時間應只有一個客戶端驅動控制模式；不仲裁併發寫入。
- 值依原樣套用；如需消抖由主機負責。
